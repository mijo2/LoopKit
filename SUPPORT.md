# Getting help

| I want to… | Go to |
| --- | --- |
| Ask how to do something, or whether loop-kit fits my use case | [Discussions → Q&A](https://github.com/OWNER/loop-kit/discussions/categories/q-a) |
| Report something that is broken | [New issue → Bug report](https://github.com/OWNER/loop-kit/issues/new?template=bug_report.yml) |
| Propose a change or feature | [New issue → Feature request](https://github.com/OWNER/loop-kit/issues/new?template=feature_request.yml) |
| Report a security problem | [SECURITY.md](SECURITY.md) — privately, please |
| Contribute code or docs | [CONTRIBUTING.md](CONTRIBUTING.md) |

Before asking, the README covers installation, providers, the `loopkit.toml`
project file, and what the loop does on each turn. `LOOPKIT_TRACE=1` (or
`loopkit ask` without `--quiet`) prints every step of the loop to stderr and is
usually the fastest way to see why an answer came out the way it did.

This is a volunteer-maintained project. Questions are answered as time allows;
a clear, minimal reproduction gets a faster answer than a long description.
